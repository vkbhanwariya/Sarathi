# Supported Document and Data Formats

Sarathi extracts, processes, and normalizes documents across modern and legacy file formats using content-inspection detection rather than trusting file extensions alone.

---

## 1. PDF & Scanned PDF

- **Native Vector PDF**: Extracted using high-performance PyMuPDF (`pymupdf`). Extracts text spans, character positions, font metrics, embedded bounding boxes, and embedded TrueType font programs (`doc.extract_font(xref)`) to identify font programs directly. Deep layout analysis with reading order recovery is supported via `pymupdf-layout` (`layout_preserving` profile).
- **Scanned / Raster PDF**: When a PDF contains no extractable vector text or tables, `native_extraction` marks the document as unpopulated (`needs_ocr=True`). Manthan automatically plans a continuation hand-off to the local OCR engine (`ocr`), which rasterizes pages and performs optical recognition.
- **Hybrid Documents**: Pages with mixed vector text and embedded images preserve native text while routing rasterized regions as appropriate.

---

## 2. DOCX (WordprocessingML)

- **Input**: Microsoft Word OpenXML `.docx` files (ECMA-376).
- **Extraction**: Reads `word/document.xml`, extracting paragraph text (`w:p`), individual runs (`w:r`), visual styling (bold, italic), embedded tables (`w:tbl`), and document heading hierarchies.
- **Output & Transformation**: Sarathi's `docx_exporter` generates standardized DOCX documents and transforms existing packages with high-fidelity layout preservation:
  - **Script-Aware Typography**:
    - **Devanagari (Hindi)**: Styled with Nirmala UI, 12 pt (`w:sz=24`).
    - **Latin / Numeric (English)**: Styled with Times New Roman, 12 pt (`w:sz=24`).
  - **Table Layout & Grid Preservation**:
    - **Proportional Column Widths**: Calculates column widths dynamically and emits `<w:tblGrid>` with `<w:gridCol>` definitions ensuring proportional text wrapping and preventing cell content truncation.
    - **Row Anti-Split Protection**: Automatically injects `<w:cantSplit/>` in `<w:trPr>` to keep table rows intact across page boundaries.
    - **Cell Margin Padding**: Configures `<w:tblCellMar>` (108 dxa top/bottom, 144 dxa left/right) for clean typographic breathing room.
    - **Flow Anchoring & Deduplication**: Inserts tables in-flow without artificial outer containers and eliminates redundant empty paragraph wrappers.

---

## 3. Spreadsheets (XLS, XLSX, SpreadsheetML)

- **Modern XLSX / XLSM**: Extracted via `python-calamine` (fast Rust-based Excel parser) with `openpyxl` fallback. Preserves multi-sheet workbooks and cell data.
- **Legacy Binary XLS (Excel 97–2003 BIFF8)**: Extracted via `python-calamine` (high-performance Rust BIFF8 parser) with `xlrd` fallback. Content format detection inspects OLE compound document headers (`\xD0\xCF\x11\xE0\xA1\xB1\x1A\xE1`) and internal BIFF stream signatures (`Workbook`, `Book`).
- **XML Spreadsheet 2003 (SpreadsheetML)**: XML-based format (`urn:schemas-microsoft-com:office:spreadsheet`) frequently generated by enterprise accounting systems. Parsed into structured sheets and tables.
- **HTML Disguised as XLS**: Files saved with an `.xls` extension that actually contain HTML `<table>` markup are detected via initial byte signatures and parsed as HTML tables.

---

## 4. Delimited Text Files

Sarathi extracts tabular data from structured text files using automatic dialect detection:

- **Supported Delimiters**:
  - Comma (`,`) — standard CSV
  - Tab (`\t`) — TSV
  - Semicolon (`;`) — European CSV
  - Pipe (`|`) — pipe-delimited data dumps
- **Dialect Sniffing**: Uses `csv.Sniffer` on the initial 4 KB buffer to determine the delimiter, quoting convention, and header structure.
- **Engine**: Parsed via `polars` for fast, memory-efficient columnar extraction.

---

## 5. Supported Text Encodings

Text files and CSVs are decoded using automatic byte inspection via `charset-normalizer`:

- **Primary Encodings**:
  - `UTF-8` (with or without BOM)
  - `UTF-16 LE` / `UTF-16 BE`
  - `Windows-1252` (`cp1252`)
  - `ISO-8859-1` (`latin-1`)
  - `ASCII`
  - `CP437`
- **Fallback Behavior**: If a file cannot be decoded with the detected charset, decoding falls back to UTF-8 with replacement characters (`errors="replace"`), logging a warning in the provenance record rather than terminating pipeline execution.

---

## 6. Legacy Hindi Fonts

Government, judicial, and enterprise documents frequently contain non-Unicode 8-bit Devanagari fonts. Sarathi provides automated detection and conversion to standard Unicode:

- **Supported Font Families**:
  - **Kruti Dev** (010, 011, 012, 014, 016, 020, 021, etc.)
  - **Devlys** (010, 020, 030, etc.)
  - **Chanakya**
  - **Shusha**
  - **Shivaji** (010, 020)
- **Detection Mechanism**:
  - **Statistical Text Signatures**: Evaluates text for characteristic legacy bigrams and sequences (e.g. `[k`, `vk`, `vks`, `ñ`, `¥æ`, `°ð`, `aA`, `bA`) with token sampling (4.2x faster evaluation). Requires at least 2 distinct signature matches.
  - **TrueType SFNT Binary Inspection**: In DOCX (`w:rFonts`) and vector PDF (PyMuPDF `doc.extract_font(xref)`), parses embedded TrueType SFNT binary headers (`name` table) to identify legacy font family names and subset prefixes (`ABCDEF+KrutiDev010`) directly without OCR.
- **Conversion Engine & Linguistic Accuracy**:
  - **Akshara Synthesis**: Maps legacy 8-bit glyph byte codes to Unicode Devanagari codepoints using 14 precompiled Akshara synthesis regular expressions and LRU-cached reph patterns accelerated with AVX2 SIMD (`rapidfuzz` and `regex`).
  - **Grammar & Phonetic Correction**: Preserves chhoti-i following Nukta, synthesizes decomposed independent vowels (`अा` -> `आ`, `अो` -> `ओ`, `अौ` -> `औ`, `अॅ` -> `ऑ`, `एे` -> `ऐ`), reorders post-matra Nukta, and normalizes typewriter half-consonant + Nukta sequences (`क़्` -> `क़्`).
  - **Mechanical Defect Repair**: Deduplicates repeated typewriter keyboard slips (`।।` -> `॥`, `़़` -> `़`, `ःः` -> `ः`) and removes stray ZWNJ codepoints.
  - **Statutory Entity Protection**: Protects critical legal and statutory acronyms (FIR, PMLA, CrPC, BNS, BNSS, BSA, IPC, etc.) from corruption during font conversion.
