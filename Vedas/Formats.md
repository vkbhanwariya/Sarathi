# Supported Document and Data Formats

Sarathi extracts, processes, and normalizes documents across modern and legacy file formats using content-inspection detection rather than trusting file extensions alone.

---

## 1. PDF & Scanned PDF

- **Native Vector PDF**: Extracted using PyMuPDF (`pymupdf`). Extracts text spans, character positions, font metrics, and embedded bounding boxes.
- **Scanned / Raster PDF**: When a PDF contains no extractable vector text or tables, `native_extraction` marks the document as unpopulated (`needs_ocr=True`). Manthan automatically plans a continuation hand-off to the local OCR engine (`ocr`), which rasterizes pages and performs optical recognition.
- **Hybrid Documents**: Pages with mixed vector text and embedded images preserve native text while routing rasterized regions as appropriate.

---

## 2. DOCX (WordprocessingML)

- **Input**: Microsoft Word OpenXML `.docx` files (ECMA-376).
- **Extraction**: Reads `word/document.xml`, extracting paragraph text (`w:p`), individual runs (`w:r`), visual styling (bold, italic), embedded tables (`w:tbl`), and document heading hierarchies.
- **Output & Transformation**: Sarathi's `docx_exporter` generates standardized DOCX documents and transforms existing packages, applying script-aware typography:
  - **Devanagari (Hindi)**: Styled with Nirmala UI, 12 pt (`w:sz=24`).
  - **Latin / Numeric (English)**: Styled with Times New Roman, 12 pt (`w:sz=24`).

---

## 3. Spreadsheets (XLS, XLSX, SpreadsheetML)

- **Modern XLSX / XLSM**: Extracted via `python-calamine` (fast Rust-based Excel parser) with `openpyxl` fallback. Preserves multi-sheet workbooks and cell data.
- **Legacy Binary XLS (Excel 97–2003 BIFF8)**: Extracted via `xlrd`. Content format detection inspects OLE compound document headers (`\xD0\xCF\x11\xE0\xA1\xB1\x1A\xE1`) and internal BIFF stream signatures (`Workbook`, `Book`).
- **XML Spreadsheet 2003 (SpreadsheetML)**: XML-based format (`urn:schemas-microsoft-com:office:spreadsheet`) frequently generated by enterprise accounting systems. Parsed into structured sheets and tables.
- **HTML Disguised as XLS**: Files saved with an `.xls` extension that actually contain HTML `<table>` markup are detected via initial byte signatures and parsed as HTML tables.

---

## 4. Delimited Text Files

Sarathi extracts tabular data from structured text files using automatic dialect detection:

- **Supported Delimiters**:
  - Comma (`,`) — standard CSV
  - Tab (`\t`) — TSV
  - Semicolon (`;`) — European CSV
  - Pipe (`|`) — pipe-delimited data dumps
- **Dialect Sniffing**: Uses `csv.Sniffer` on the initial 4 KB buffer to determine the delimiter, quoting convention, and header structure.
- **Engine**: Parsed via `polars` for fast, memory-efficient columnar extraction.

---

## 5. Supported Text Encodings

Text files and CSVs are decoded using automatic byte inspection via `charset-normalizer`:

- **Primary Encodings**:
  - `UTF-8` (with or without BOM)
  - `UTF-16 LE` / `UTF-16 BE`
  - `Windows-1252` (`cp1252`)
  - `ISO-8859-1` (`latin-1`)
  - `ASCII`
  - `CP437`
- **Fallback Behavior**: If a file cannot be decoded with the detected charset, decoding falls back to UTF-8 with replacement characters (`errors="replace"`), logging a warning in the provenance record rather than terminating pipeline execution.

---

## 6. Legacy Hindi Fonts

Government, judicial, and enterprise documents frequently contain non-Unicode 8-bit Devanagari fonts. Sarathi provides automated detection and conversion to standard Unicode:

- **Supported Font Families**:
  - **Kruti Dev** (010, 011, 012, 014, 016, 020, 021, etc.)
  - **Devlys** (010, 020, 030, etc.)
  - **Chanakya**
  - **Shusha**
  - **Shivaji** (010, 020)
- **Detection Mechanism**:
  - **Statistical Text Signatures**: Evaluates text for characteristic legacy bigrams and sequences (e.g. `[k`, `vk`, `vks`, `ñ`, `¥æ`, `°ð`, `aA`, `bA`). Requires at least 2 distinct signature matches.
  - **TrueType SFNT Binary Inspection**: In DOCX and PDF documents, parses the embedded TrueType SFNT binary header (`name` table) to identify legacy font family names directly.
- **Conversion Engine**: `font_conversion` maps legacy 8-bit glyph byte codes to Unicode Devanagari codepoints while retaining punctuation, numerals, and paragraph layout.
